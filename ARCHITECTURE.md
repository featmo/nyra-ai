# RealtimeSTT — Project Architecture & Modular Design

## Overview

**RealtimeSTT** (`KoljaB/RealtimeSTT`) is a Python speech‑to‑text library for real‑time applications. It provides voice activity detection (VAD), fast transcription, optional wake‑word activation, and direct audio stream access.

The package follows a **pluggable‑engine** design: a thin `TranscriptionEngine` interface is implemented by multiple back‑ends (Whisper, Sherpa‑ONNX, Porcupine, OpenAI Whisper, etc.). This makes it easy to swap back‑ends without touching the core logic.

## Key Design Principles

| Principle | Implementation |
|-----------|----------------|
| **Separation of Concerns** | Core audio/VAD logic is decoupled from back‑ends. Each engine implements `TranscriptionEngine`. |
| **Plugin‑style Extensibility** | New back‑ends are added as new modules under `transcription_engines/`. No core change required. |
| **Optional Dependencies** | All back‑ends are behind `extras_require` groups (`faster-whisper`, `sherpa-onnx`, `porcupine`, …). Users pick what they need. |
| **CLI First** | Entry points (`stt`, `stt-server`, `stt-install-kroko`, …) let users interact with the library from the terminal. |
| **Production Ready** | Includes a FastAPI server (`RealtimeSTT_server`), a production‑grade server recipe, and a Kroko‑ONNX builder. |

### 3. Core Abstraction (`src/realtimestt/core/engine.py`)

```python
from abc import ABC, abstractmethod
from pathlib import Path

class TranscriptionEngine(ABC):
    """Abstract base for all transcription back‑ends."""

    @abstractmethod
    def transcribe(self, audio_path: Path) -> dict[str, str]:
        """Return {
            'text': str,
            'language': str | None,
            'start_time': float | None
        }
        """
        ...

    @abstractmethod
    def supports_vad(self) -> bool:
        """True if the engine handles voice‑activity detection."""
        ...
```

Each concrete engine (e.g., `faster-whisper.py`) implements these methods. The core simply calls `engine.transcribe()`. This is the **single biggest win** for modularity: swapping from Whisper to Sherpa‑ONNX requires zero changes to the rest of the codebase.

### 4. Backend Implementations

| Engine | Backend | Best For |
|--------|---------|----------|
| `faster-whisper` | `faster-whisper` (GPU/CPU) | General purpose, lowest latency |
| `sherpa-onnx` | `sherpa-onnx==1.13.4` | Low‑latency streaming, production server |
| `porcupine` | `pvporcupine` | Wake‑word + transcription combo |
| `openai-whisper` | `openai-whisper` | Cloud‑based Whisper (if you want remote processing) |
| `kroko-builder` | `huggingface_hub` + local model | Local streaming ASR (Kroko‑ONNX) |

All engines share the same **interface**, so the rest of the code (recording, VAD, callbacks) stays untouched.

### 5. CLI Entry Points

Using `setuptools` entry points (or `uv` equivalent) you get:

```bash
$ stt --help
Usage: stt [-h] [--out OUTPUT] [--engine ENGINE]

Options:
  --out, -o OUTPUT   Output WAV path (default: recording.wav)
  --engine, -e ENGINE   Choose engine: faster-whisper, sherpa-onnx, porcupine, openai-whisper
```

This is a clean, discoverable way to expose functionality without publishing a separate package.

### 6. Production Server (`src/realtimestt/server/main.py`)

- **FastAPI** with WebSocket for real‑time text streaming.
- Separate **HTTP** endpoint for RESTful transcription requests.
- Health checks, readiness probes, and authentication (via `uvicorn` middleware).
- Can be started with `uv run realtimestt.server.main:app`.

### 7. Testing Strategy

- **Unit tests** for each engine (mock audio, verify output format).
- **Integration tests** that spin up the FastAPI server and send audio chunks.
- **CI** (GitHub Actions) runs `pytest` on the `tests/` directory.
- **Performance benchmarks** comparing Whisper vs. Sherpa‑ONNX latency.

## Why This Architecture Works

1. **No hidden coupling** – The core knows nothing about Whisper, Sherpa, or Porcupine except the abstract interface.
2. **UV friendly** – `pyproject.toml` + `uv` gives lightning‑fast builds and deterministic installs.
3. **Extensible** – Adding a new back‑end is a single new file under `transcription_engines/`; no existing code changes.
4. **Production ready** – The server component, FastAPI routes, and health checks are already there.
5. **User‑centric** – The CLI gives immediate value without needing to learn the library internals.
